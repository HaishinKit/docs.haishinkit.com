haishin_kit

haishin_kit library

Capture, mix, preview, publish, and play audio and video on native platforms.

Use MediaMixer to attach input sources and compose overlays through its Screen, StreamSession for network sessions, and StreamSessionViewTexture for native video previews and playback.

Platform integration

Use Flutter 3.44+, Dart 3.12+, and Xcode 26+ for Apple builds. The native Apple bridge uses HaishinKit.swift 2.3.1 through Swift Package Manager, targeting iOS 15 and macOS 12. CocoaPods installation of this plugin is not supported. Enable Swift Package Manager before resolving the consuming app:

flutter config --enable-swift-package-manager
flutter clean
flutter pub get

Add camera/microphone usage descriptions to the app's iOS/macOS Info.plist:

<key>NSCameraUsageDescription</key>
<string>Use the camera for publishing.</string>
<key>NSMicrophoneUsageDescription</key>
<string>Use the microphone for publishing.</string>

On macOS, enable com.apple.security.device.audio-input and com.apple.security.device.camera in the app's Debug and Release entitlements.

Android uses HaishinKit.kt 0.20.5 modules from JitPack and OpenGL composition. Use compile SDK 37+. The native bridge declares API 23, while Flutter 3.44 requires an Android app minimum of API 24. With the repository's current Kotlin plugin configuration, set these Android Gradle properties:

android.builtInKotlin=false
android.newDsl=false

Request camera and microphone permissions before capture. Android WHIP audio publishing needs an Opus encoder (available on Android 10+) and 48 kHz PCM. Plain HTTP requires the consuming app to allow cleartext traffic in its Android network-security configuration.

Publishing and session lifecycle

The transport comes from the URL. Include the RTMP stream name in the full RTMP/RTMPS URL; pass complete SRT URLs with their query options. WHIP publishes and WHEP plays back using their respective complete HTTP(S) endpoints.

final mixer = await MediaMixer.create();
await mixer.attachAudio(0, AudioSource(sampleRate: 48000));
final cameras = await HaishinKitPlatformInterface.instance.videoSources;
if (cameras.isEmpty) throw StateError('No camera is available.');
await mixer.attachVideo(0, cameras.first);
final session = await StreamSession.create(
  'https://example.com/whip',
  StreamSessionMode.publish,
);
await mixer.startRunning();
await session.connect();
// When finished, including after failure or cancellation:
await session.close();
await session.dispose();
await mixer.dispose();

Observe StreamSession.readyState and handle StreamSessionException from connection attempts. The 48 kHz capture option in this example applies to Android; native capture behavior on Apple platforms is managed by the bridge. Android WHIP uses Opus and H.264 Baseline level 3.1, so keep custom video settings within those capabilities.

Playback

final session = await StreamSession.create(
  'https://example.com/whep',
  StreamSessionMode.playback,
);

Put StreamSessionViewTexture in the widget tree before calling StreamSession.connect. Close and dispose the session when playback finishes. SRT and HTTP(S) endpoints preserve paths/query parameters and do not use a separate RTMP stream-name field. The Dart API currently uses native default ICE/authentication settings, without parameters for bearer tokens or STUN/TURN.

Developing the plugin

Regenerate data classes after editing their source definitions:

dart run build_runner build --delete-conflicting-outputs
